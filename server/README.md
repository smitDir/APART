# apart-server

Backend для бронирования Tvoy Apart 24/7. Node.js + Express + MySQL.

## Запуск локально

Нужен доступный MySQL/MariaDB сервер (локально или на VPS) и пустая база
(см. `DB_NAME` в `.env`) — схема и начальные данные создаются автоматически
при первом старте (`server/src/db.js`, `init()`/`seed()`).

```bash
cd server
npm install
cp .env.example .env   # заполнить DB_* и остальными реальными ключами
mysql -u root -e "CREATE DATABASE apart; CREATE USER 'apart'@'localhost' IDENTIFIED BY '...'; GRANT ALL ON apart.* TO 'apart'@'localhost';"
npm start
```

Без заполненных `YOOKASSA_*`/`TELEGRAM_*` сервер работает: заявки сохраняются,
оплата по ссылке не создаётся (просто `confirmationUrl: null`), уведомления
пишутся в консоль вместо Telegram, бот не запускается (только лог в консоль).

**Каждый проект/направление — своя база данных** на одном MySQL-сервере VPS
(один `DB_NAME` на проект), а не общая база на всё. Так проще держать данные
разных бизнесов изолированными и не думать о префиксах таблиц.

## Telegram-бот (бронирование через чат)

С заполненным `TELEGRAM_BOT_TOKEN` при старте сервера поднимается бот
(`server/src/bot`, long polling). Команды: `/start`, `/book`, `/menu`,
`/manual`, `/emergency`, `/events`, `/manager`, `/cancel`. Бронь создаётся
через тот же `bookingService`, что и форма на сайте — единый источник данных
и единая проверка занятости дат.

Меню питания/трансфера и тексты инструкций/экстренных служб/мероприятий
хранятся в таблицах `menu_items` / `property_content` — редактируются
напрямую в БД (`mysql -u apart -p apart`), без правки кода.

Согласие на обработку ПД/договор/правила проживания — простое согласие в
боте (кнопка «Согласен»), лог сохраняется в таблице `consents`
(booking_id, telegram_user_id, тип документа, время). Это не
квалифицированная электронная подпись — офферта-акцепт.

### Свободный диалог (AI-слой)

Если гость пишет боту произвольным текстом вне активного сценария (`/book` и
т.п.), сообщение уходит в Gemini (`GEMINI_API_KEY` — бесплатный тариф на
[Google AI Studio](https://aistudio.google.com/apikey)) вместе с историей
переписки (`chat_messages`, последние 20 сообщений на чат) и базой знаний,
собранной из `property_content`/`menu_items` (`server/src/ai/knowledgeBase.js`).
Без ключа бот отвечает заглушкой со списком команд вместо падения.

Это НЕ векторный RAG — вся база знаний по объекту помещается целиком в
системный промпт, что нормально для одной квартиры. Если объектов/документов
станет много, тут нужно будет переходить на настоящий RAG (эмбеддинги +
векторный поиск) — пока это избыточно.

Каждый AI-ответ идёт с кнопкой «Написать менеджеру» — эскалация к человеку
всегда в одно касание.

## Развёртывание на VPS

1. Node.js 20+, MySQL/MariaDB сервер (общий на VPS, отдельная база `DB_NAME` под этот проект), `npm install --production`.
2. Заполнить `.env` реальными ключами ЮKassa, Telegram и параметрами `DB_*`.
3. Запускать как systemd-сервис или через `pm2 start src/index.js --name apart-server`.
4. nginx: проксировать домен `apart247.ru` (отдельный от лендинга, только под API) на `localhost:3000`, HTTPS через certbot.
5. В `index.html` заменить `window.APART_API_BASE_URL` на реальный адрес API (или задать глобальную переменную перед подключением скрипта).
6. В ЮKassa указать webhook URL: `https://apart247.ru/api/webhooks/yookassa` (событие `payment.succeeded`).

## Контент-конвейер (посты в Telegram-канал)

Разделение обязанностей: генерация медиа (фото/видео через RunComfy) выполняется
отдельно — через уже установленный в этой среде навык/CLI `runcomfy`
(например, навыки `ai-image-generation`, `ai-video-generation`), а этот сервер
отвечает только за очередь и надёжную публикацию по расписанию.

1. Создать черновик поста: `POST /api/admin/posts` `{ "channel": "telegram", "caption": "...", "mediaPrompt": "..." }`
2. Сгенерировать медиафайл по `mediaPrompt` через RunComfy CLI, сохранить локально.
3. Прикрепить путь к файлу: `POST /api/admin/posts/:id/media` `{ "mediaPath": "/path/to/file.jpg" }` — переводит пост в статус `generated`.
4. Публикация: `node src/content/run.js` — публикует все посты в статусе `generated`, у которых `scheduled_at` наступил (или не задан). Повесить на cron, например каждые 5 минут:
   ```
   */5 * * * * cd /path/to/server && node src/content/run.js >> /var/log/apart-content.log 2>&1
   ```

YouTube: публикация появится отдельным шагом после того, как будет создан
YouTube-канал и настроен OAuth-доступ к YouTube Data API v3 (интерактивный
шаг, требует входа в аккаунт Google — не может быть сделан автоматически).

### Еженедельное предложение постов

Первые 2 месяца — планирование раз в неделю, дальше раз в месяц (см. TZ.md 8.10).
Посты предлагаются и утверждаются пакетом на неделю, а не по одному:

1. Задать тему месяца: `POST /api/admin/themes` `{ "month": "2026-07", "theme": "..." }`
2. Предложить пакет постов на неделю: `POST /api/admin/posts/week`
   ```json
   { "weekOf": "2026-07-06", "theme": "...", "posts": [
     { "contentType": "photo", "caption": "...", "mediaPrompt": "...", "scheduledAt": "2026-07-06 12:00" }
   ] }
   ```
3. Посмотреть пакет: `GET /api/admin/posts/week/:weekOf`
4. Утвердить пакет целиком: `POST /api/admin/posts/week/:weekOf/approve`
5. Дальше — как обычно: сгенерировать медиа, прикрепить (`/posts/:id/media`), опубликовать (`content/run.js`).

**Важно про рекламные правила площадок (РФ):** платное размещение рекламы у
сторонних каналов/блогеров требует маркировки (`erid`-токен через Оператора
рекламных данных, закон о маркировке рекламы). Собственные посты о своих же
услугах на своём канале под эту маркировку не подпадают — но если когда-либо
будете платить другим каналам за упоминание Apart, это уже требует маркировки.

## Ручное подтверждение оплаты по реквизитам

Оплата картой/по ссылке подтверждается автоматически через вебхук ЮKassa.
Оплата переводом по реквизитам подтверждается вручную менеджером:

```bash
curl -X POST -u admin:PASSWORD https://apart247.ru/api/admin/bookings/<id>/confirm
```
